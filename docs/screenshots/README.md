# Screenshots

Visual assets used in the top-level README + GitHub social card.

## What goes here

- `hero.png` — the wide hero strip used in the README's lead. Suggested 1200×600, a clean shot of the party page in active state with a few claimed squares + scoreboard visible.
- `filling.png` / `active.png` / `complete.png` — the three states used in the social card / promotional material.
- `demo.gif` — ~10 second walkthrough: create → claim → lock → score → see winners.

## How to regenerate

These are a manual capture step — they're not generated by the build. The test suite has separate visual regression baselines under `e2e/visual.spec.ts-snapshots/` for CI; those are not the same files.

### Screenshots

```bash
# Start a clean preview build with seeded demo data
supabase start
supabase db reset
npm run build && npm run preview
# Open http://localhost:4173, navigate through the app, capture
# Save raw .png files to docs/screenshots/
# (drop hero.png, filling.png, active.png, complete.png in here)
```

### Demo GIF

```bash
# 1. Record screen with QuickTime (or your tool of choice)
#    Save raw .mov to docs/screenshots/raw/demo.mov
#    (raw/ is gitignored — keep originals out of the repo)

# 2. Convert to optimized GIF (target ≤ 2 MB)
ffmpeg -i raw/demo.mov \
  -vf "fps=12,scale=720:-1:flags=lanczos" \
  -loop 0 \
  docs/screenshots/demo.gif

# 3. Verify size
du -sh docs/screenshots/demo.gif
```

If the GIF exceeds 2 MB, drop fps to 10 or scale to 640.
